> 适用于：拿到一台全新租用的 RTX 5090 Linux 实例（平台 PyTorch/CUDA 12.8 系镜像即可，

> 重跑同一条命令即可续接。

**第 0 步 · 获取代码与数据**（本机 → 云端）


## 2. 赛题要求完整整理

### 2.1 赛题背景与目标

**背景**：基于 AIGC 的图像增强方法在复杂场景下常面临**可控性不足**的问题，易导致细节失真或过度处理，难以在提升画质的同时保持内容真实自然。

**目标**：使用 AIGC 模型对输入图像中具有挑战性的场景元素进行高质量、可控的图像增强，覆盖五类挑战场景：

> **小人脸、文字、密集绿植、钟表、鸟类**

**硬性要求**（逐条为验收红线）：

| # | 要求 | 技术含义 |
|---|---|---|
| R1 | 显著提升清晰度 | 细节/纹理重建能力 |
| R2 | 保持真实与自然感，**避免伪影或失真** | 生成可控性，防幻觉纹理 |
| R3 | 处理前后**图像内容一致** | 禁止改变语义内容（改字、改脸、加删物体） |
| R4 | **分辨率不变**（4K→4K） | 同分辨率增强，非超分；输出尺寸必须严格等于输入 |
| R5 | 色彩与结构自然协调 | 全局色调/亮度不可漂移 |
| R6 | **模型需采用 Diffusion 架构** | 排除 GAN-only、回归式网络方案 |
| R7 | 最终与理想参考图（GT）比较评分 | 有参考指标权重大，保真度关键 |

### 2.2 数据集构成

| 数据集 | 规模 | 说明 |
|---|---|---|
| val（官方称验证集） | 5 组数据对 | 每组含输入图 + 参考图（GT），供自行验证算法效果，**无需提交** |
| test（官方称测试集） | 100 组低质量图像 | GT 不公开，覆盖五类挑战场景，分辨率均为 **4K**，需全部增强后提交 |

### 2.3 初赛提交要求

- 提交 100 组测试图像的处理结果，**jpg 格式**，文件名与输入严格一一对应（输入 `case1` → 结果 `case1.jpg`）。
- 结果不要包含中文符号。
- 所有结果存储到 `output_dir` 文件夹并打包为 `.zip`：

```text
my_work.zip
└── output_dir
    ├── case1.jpg
    ├── case2.jpg
    ├── case3.jpg
    └── ......
```

- 作品命名规范：`技术领域+作品名称+团队/个人名称+联系方式`，示例：`赛题一_xxx作品_xx队_13000000000.zip`。
- 作品名尽量简洁，不含汉字状态符号；上传格式限 zip，大小 **≤ 10GB**。
- 初赛阶段**最多提交 10 次**，截止时榜单前 10 名进入决赛。

### 2.4 决赛要求

- 准备**方案综述 PPT** 一份，现场介绍生成式模型的可控性设计思路与实验结果。
- **现场处理**决赛提供的 **20 组新测试图像**并现场算分。
- 考察点：五类挑战场景的生成可控性。
- 总分 = 评委提问打分 + 现场测试计算分数。

### 2.5 考核指标

- 通过增强图像与 GT 的比较计算，使用**多项有参考 + 无参考指标**综合评估。
- 综合得分 Score = 各项指标的**加权平均值**；具体指标与权重**在决赛入围名单公布时才公开**。
- 最终排名按综合得分排序。

## 4. 关键约束与技术难点分析

1. **评分权重未知（最大不确定性）**
   官方综合分 = 有参考 + 无参考指标加权，权重 9/20 才公布。有参考指标（PSNR/SSIM/LPIPS）对**色彩、亮度、全局色调**极度敏感；无参考指标（MUSIQ/CLIPIQA 类）奖励锐利纹理与生成细节。两者存在天然张力：生成越多，感知分越高、保真分越低。
   **对策**：管线支持"保真 ↔ 生成"连续调节，用 val 扫描平衡点，不押宝单一指标。

2. **4K 同尺寸全图处理**
   主流扩散复原模型原生只处理 512/1024。4K（12.6M 像素）必须分块推理 + 重叠羽化融合，且接缝处不得产生伪影；显存/存储/时间成本都要按 100 张 × 4K 估算。

3. **内容一致性红线**
   扩散模型在文字、人脸区域极易"改写内容"（换字、换脸）。这两类区域需要提高保真权重，必要时锁定低频。

4. **提交次数稀缺**
   10 次提交要用在刀刃上：1 次试水校准 + 6 次方向迭代 + 2 次锁定确认 + 1 次应急。每次提交前必须过本地评测闸门。

5. **Diffusion 架构硬约束**
   排除非扩散方案；同时意味着算力开销大，必须依赖云端 5090。

## 5. 总体技术方案

### 5.1 三层管线架构

```text
输入 4K LQ
   │
   ▼
┌─────────────────┐   ① 预处理：轻量去噪/去模糊，抑制 case1 级强噪，
│   ① 预处理层     │      避免噪声被扩散模型当"细节"放大成幻觉纹理
└─────────────────┘
   │
   ▼
┌─────────────────┐   ② 扩散复原核心：Diffusion 架构（赛题硬性要求）
│  ② 扩散复原层   │      主选 DiffBIR 两阶段（通用复原 + 生成细化）
└─────────────────┘      4K 输入 → 分块推理 → 重叠羽化融合 → 4K 输出
   │
   ▼
┌─────────────────┐   ③ 后处理对齐：低频回填（色彩/亮度对齐输入，
│  ③ 后处理层     │      压住色调漂移 → 拉高 PSNR/SSIM）
└─────────────────┘      λ 混合系数调节保真↔生成比例
   │                     人脸分支：检测→专用增强→融合回图
   ▼
输出 4K（尺寸与输入严格一致）
```

### 5.2 模型选型

| 优先级 | 模型 | 理由 | 风险 |
|---|---|---|---|
| **主选** | **DiffBIR**（SD2.1 底座） | 两阶段设计（保真复原 + 生成细化）天然契合"可控性"赛题；社区代码成熟；可控参数多 | 需分块推理工程化 |
| 备选1 | ResShift | 轻量快速扩散复原，保底方案，8GB 本地卡也能跑 | 生成能力弱于 DiffBIR |
| 备选2 | PASD | 像素对齐扩散，保真好 | 文字场景可控性待验证 |
| 观望 | SUPIR（SDXL 底座） | 效果天花板 | 5090 上可行但重；时间紧时不折腾 |

**原则**：9 天赛期只做**推理 + 工程优化 + 后处理调参**，不做训练/微调。

### 5.3 保真-生成平衡机制（提分核心）

- **低频回填**：将输入图的低频分量（色彩/亮度/大结构）回填到输出，公式化表达：

  ```text
  final = blend(output_model, lq_lowfreq)   # 高斯金字塔或多尺度融合
  ```

- **λ 混合系数**：`final = λ · 生成增强 + (1-λ) · 保真复原`，在 val 5 组上扫 λ ∈ {0.3, 0.5, 0.7, 0.9}，选 FR/NR 综合最优。
- **色彩对齐**：输出与输入做均值/方差（或多尺度）色彩统计对齐，直接利好 PSNR/SSIM。

### 5.4 五类场景适配策略

| 场景 | 风险 | 策略 |
|---|---|---|
| 小人脸 | 换脸级失真（内容不一致） | 人脸检测 → 人脸区域专用增强（GFPGAN/CFPD 类）→ 高保真融合 |
| 文字 | 改字、笔画变形 | 文字区域提高保真权重/锁定低频，只做去噪锐化 |
| 密集绿植 | 幻觉枝叶、纹理糊成一片 | 正常生成流程，注意分块融合自然度 |
| 钟表 | 刻度/指针被改 | 结构敏感区域保真优先 |
| 鸟类 | 羽毛纹理幻觉 | 正常生成流程，观察 NR 指标收益 |

### 5.5 云端算力计划

- 租用 **RTX 5090（默认 60GB 存储）** 作为主力训练/推理机；本地 4060 仅用于代码调试与小图验证。
- 模型权重（DiffBIR + SD2.1 约 6~8GB）在 60GB 存储内可容纳，注意清理 pip 缓存。
- 云端环境用脚本固化（`environment/setup_5090.sh`，幂等可重跑），保证：本地调试 → 云端全量跑 → **决赛现场复现** 三者环境一致。

## 6. 评测体系

### 6.1 本地指标（模拟官方综合分）

| 类别 | 指标 | 工具 |
|---|---|---|
| 有参考 FR | PSNR、SSIM、MS-SSIM、LPIPS、DISTS | pyiqa / 自实现 |
| 无参考 NR | MUSIQ、CLIPIQA、NIQE、MANIQA | pyiqa |

综合分按多套候选权重组合计算（等权、FR 偏重、NR 偏重），观察配置在不同权重下的稳健性。

### 6.2 评测流程

1. 每个实验在 **val 5 组**上全流程跑完 → 指标 JSON 落盘到 `experiments/`；
2. 评测脚本输出各指标 + 各候选权重下的综合分对照表；
3. 只有本地综合分**不劣于当前最优**的配置，才消耗官方提交额度验证；
4. 第 1 次官方提交后，用官方分数与本地分数做**相关性校准**，修正本地权重假设。

> ⚠️ 纪律：本地验证分**永远不得**在对外表述中写成"官方分数"。

### 7.2 Git 纪律与协作分工（2026-09-06 约定）

- 分支：`main` 保持可复现稳定态；实验在 `exp/<run主题>` 分支进行，结论合回 main。
- 提交按**里程碑**进行（跑通管线 / baseline 建立 / 每个候选家族 / 提交包冻结），不按时间随手提交；前缀 `feat:/fix:/docs:/exp:`。
- 数据集、权重、提交 zip、缓存一律不入库；配置与指标 JSON 必须入库（可复现的最小闭环）。
- 远程：`origin = https://github.com/WHGD666/Deep-Generative-Prior.git`，里程碑推送。

**协作分工四原则**：

1. **命令分工**：环境安装、模型下载等大任务由 AI 提供完整命令，**用户本人执行**；AI 不代跑大任务。
2. **本地先行**：一切代码/文档先在本地项目内创建写好，再谈提交上传。
3. **上传纪律**：只上传关键代码、总结文档与**已验证**的内容；数据、权重、产物、临时文件杜绝入库。
4. **强制审计**：每次里程碑提交前做代码审计（staged diff 逐项审查 + 测试 + 检查清单核对），宁多耗 token 不出错。

### 7.3 实验记录规范（run manifest）

每个**正式实验**分配唯一 `run_id`，模式：`<日期>_<主题>_<短哈希>`，如 `20260908_diffbir_baseline_a3f2`。

`experiments/<run_id>/manifest.json` 最小字段（由 `run_pipeline` 自动生成，含逐图状态与失败记录）：

```json
{
  "run_id": "20260908_diffbir_baseline_a3f2",
  "status": "completed | failed",
  "role": "diagnostic | scientific | competition | final",
  "git_commit": "<commit hash>",
  "config": "configs/20260908_diffbir_baseline_a3f2.yaml",
  "model": "DiffBIR + 权重文件名及哈希",
  "data": "val 5 组 md5 清单（data_fingerprint）",
  "command": "完整可复现命令行",
  "hardware": "RTX 5090 / 4060",
  "metrics": {"psnr": 0, "ssim": 0, "lpips": 0, "musiq": 0, "niqe": 0},
  "composite": {"equal_weight": 0, "fr_heavy": 0, "nr_heavy": 0},
  "outputs": "experiments/<run_id>/ 输出图片路径",
  "notes": "结论与下一步"
}
```

- 失败的正式 run **保留记录**（失败类型、日志、结论），不得静默删除。
- 一次只改一个有意义的变量，保证可归因；两个结果只有共享同一评测口径才能比较。

## 10. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 扩散模型改写文字/人脸 | 内容一致性重扣分 | 敏感区域保真加权 + 低频锁定；输出与输入做语义一致性抽查 |
| 分块接缝伪影 | 视觉质量 + 无参考指标下降 | 重叠羽化融合；接缝位置随机化；成片人工抽检 |
| 官方权重未知导致方向误判 | 提交额度浪费 | 第 1 次提交即做本地-官方分数校准；保持 FR/NR 均衡解 |
| 4K × 100 张算力/时间不足 | 赶不上截止 | 5090 并行多卡排队；必要时降采样→增强→升回 4K 的保底管线（仍为 Diffusion 架构） |
| 云盘 60GB 溢出 | 环境崩溃 | 权重只保留主干；pip/hf 缓存定期清理；产物及时回传本地 |
| val 过拟合（仅 5 组） | test 泛化差 | 调参只在 val 选方向，极端参数（如 λ→0/1）不采纳 |

## 附：赛题原文要点备份

> 请使用AIGC模型对输入图像中具有挑战性的场景元素（如小人脸、文字、密集绿植、钟表、鸟类等）进行高质量、可控的图像增强。要求在显著提升图像清晰度的同时，保持增强结果的真实性与自然感，避免引入伪影或失真。处理前后需确保图像内容一致，分辨率不变，色彩与结构自然协调。最终结果将依据其与理想高质量参考图像（Ground Truth）的接近程度进行评分。
>
> 本赛题的评价指标通过增强后图像和Ground Truth的比较计算得到，使用多项有参考和无参考指标进行综合评估。其综合得分 Score 为各项指标的加权平均值（具体计算指标方法在决赛入围名单时公布）。
>
> 模型需采用Diffusion架构。
