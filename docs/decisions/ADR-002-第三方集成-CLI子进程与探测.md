# ADR-002：第三方扩散模型的集成方式

- 状态：**已接受**
- 日期：2026-09-06
- 关联：ADR-001（选型 DiffBIR）；`src/enhance/backends/__init__.py`

## 背景

赛期 9 天，DiffBIR/ResShift 均为第三方仓库，其内部 API（模型构造、权重加载、
LDM 细节）随版本演进，且远程环境无法预先逐一验证；本地 4060 也不能承担
"先试错再固化"的开发循环。若直接 import 其内部 API，任何上游变动都会
击穿我们的代码，而定位这类破坏在 9 天赛期内代价极高。

## 候选方案

| 方案 | 优势 | 劣势 |
|---|---|---|
| A. import 第三方内部 API，逐 tile 调用 | 无子进程开销；单次加载 | 强耦合内部 API；易被上游变更击穿 |
| B. CLI 子进程驱动 + 我们自己的分块引擎 | 接口面=官方 CLI 参数（最稳定）；显存隔离；后端可替换 | 每图一次模型加载开销（可接受：100 图 × ~1min） |
| C. Fork 并改造第三方 | 彻底可控 | 时间不允许 |

## 决策

采用 **B（CLI 子进程 + 探测）**，配套三道防线：

1. **分块引擎自有化**：切块/羽化/融合全部自研（`src/preprocess/tiling.py`），
   有无损往返单测，不依赖第三方的 tiling；
2. **倍率探测**：后端是 ×4 超分还是 ×1 修复，运行时用 128px 探测块实测
   （`infer_upscale`），绝不在代码里硬编码假设；
3. **远程冒烟测试**：`tests/test_smoke_diffbir.py`（remote 标记）在真实
   环境验证 CLI 可用性，作为全量跑图前的强制闸门。

## 影响

- 每图一次 CLI 调用带来约 100 次模型加载（~1min/次），总开销 ~1.5h，可接受；
- 后端输出为 png 中间格式，最终由管线统一写 jpg（quality=95, 4:4:4）；
- DiffBIR CLI 参数名若与预期不符，冒烟测试会立即暴露，
  按 `environment/TROUBLESHOOTING.md` #5 处置，并用 `extra_args` 应急透传。
